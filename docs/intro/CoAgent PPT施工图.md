## P3 · 方案 The Solution 🟢（与模板完美契合）

**一句话：** 我们做了一个**「Agent 事故指挥官」**，让 **FDE / 值班 / 客户 IT** 用一张卡片完成**「从诊断到处置生产事故」**。

| 模板能力位 | 填什么 |
|------------|--------|
| CAPABILITY 01 | **看见问题**：接入事件与指标，把运行失败 / 质量异常 / 成本失控识别为「事故」 |
| CAPABILITY 02 | **诊断问题**：根因假设 + 证据链 + 把握度评分（该信什么、有多大把握） |
| CAPABILITY 03 | **处理问题**：处置合同（🟢可执行 / 🟡需确认 / 🔴必须升级）+ 飞书协同 + 受控动作 |

> 页脚/口播差异句：别人把「看见、诊断、处理」拆在不同工具、还停在屏幕上；CoAgent 收进一个闭环，帮你动手。

## P5 · 架构 Architecture 🟡（翻译成模板词汇）

| 模板层 | 填什么（CoAgent 对应物） |
|--------|--------------------------|
| INTERACTION | 管理台 Web · `POST /events` API/Webhook · 飞书 IM |
| AGENT CORE · Planner | **Orchestrator**（事件编排 + 超时预算） |
| AGENT CORE · Tool Router | **PlaybookEngine**（路由 + metrics/config/ops_playbook 工具） |
| AGENT CORE · Memory | **SQLite 全链路持久化**（事故/审计/统计） |
| AGENT CORE · Evaluator | **把握度 Scorer**（三因子评分 + 🟢🟡🔴 分级） |
| FOUNDATION | **OpenAI 兼容 LLM**（默认 gpt-4o-mini，支持 Claude / 多模型路由）⚠️ 演示时把 `LLM_BASE_URL` 指向**小宿 API** 即对齐模板 ｜ 向量库 RAG = 后期，**别填** ｜ 业务工具/MCP = 按需 |

**3 技术亮点（挑最硬的）：**
- HL 01 **把握度评分**：数据·手册·推理三因子，把「有多大把握」量化。
- HL 02 **风险分级处置合同**：风险判断直接约束动作权限 + 审批边界。
- HL 03 **结果验证飞轮**：事故前后对比反哺手册/规则，越用越准。
- （备选：想秀深度可把 HL03 换成 **Ultra 知识图谱 / What-if 推演**。）

> ⚠️ 确认：小宿是否提供 OpenAI 兼容端点？是 → 架构照填、演示切端点；否 → Foundation 据实写。
